## Responsibility decision

`incorporate` replaces the active `review-feedback` leaf. The package retains one
implicit router, twelve explicit leaves, twelve router references, and seventy
manifest-owned files. Technical feedback verification and bounded correction
propagation remain conditional parts of Incorporate. The existing glyph is

The method owns a specific commission: decide what specified material should
contribute to existing work, then carry the adopted effects as far as the current
request requires. The material defines coverage, the project supplies context,
and the request determines whether to assess, design, implement, or verify.

| Responsibility | Owner |
| --- | --- |
| Source coverage, discourse corrections, applicability, and adopted effects | `incorporate` |
| Open product or architecture choices | `design` |
| Responsibility allocation and worker integration | `delegate` |
| Already accepted specification, settled execution, and verification | Existing appropriate methods |

An incidental article does not create an incorporation task. Understanding a body
of work can be a complete commission in its own right. A reading worker is an
optional allocation of responsibility; a worker can also own a complete bounded
incorporation task. No fixed pipeline, source registry, report, or approval round
is introduced. No other plugin is required.
