Servotab 0.6.4 is the evidence-scoped debugging release. GitHub publication, directory submission, installation, activation, website deployment and live model evaluation remain separately evidenced states; publishing this release does not establish the later ones.

## Changes

This release builds the merged discussion-intake rehearsal into a 24-case source pack and sharpens existing `debug` and `verify` decisions, with a narrow alignment of the `execute` failure-handling handoff, without adding a skill, runtime service, dependency, required report or evaluation runner. The existing router already covers unknown causes, conflicting evidence and repeated failure; it stays unchanged.

`debug` separates the mechanism experiment from final acceptance. A surrogate must preserve the conditions relevant to the tested cause. Trial results can be supportive, contradictory or inconclusive; an unverified intervention or failure to restore the whole experience does not erase a contributing defect. Direct boundary violations and loss of discriminating evidence prompt an earlier diagnostic reset. Counts remain a backstop, and a reset does not automatically require an architecture search. Permanent repairs follow component and lifecycle ownership.

`execute` failure handling now points at the same evidence rule instead of a mechanical two-attempt reset: test one discriminating causal claim at a time, retain independently observed defects, and reset only when repeated attempts on one idea stop adding discriminating evidence.

`verify` checks probe entry, path and conditions, pairs disappearing errors with successful outcomes, separates mechanism repair from complete recovery, and prefers structured or stable normalized before-images for state-preservation claims.

## Diagnostic cases

Three cases extend the merged 21-case source pack (20 prior cases plus the `discussion-intake` rehearsal) to twenty-four:

- `cross-boundary-diagnosis`: a local executable admission model with healthy bypass probes, a confounded earlier trial and an independent residual delay. Acceptance requires actual comparable pre/post experiments and successful delivery, not a proposed plan or an edited counter.
- `host-specific-diagnosis`: a desktop probe lacks a material native-host condition and cannot exclude that cause.
- `diagnosis-progress`: successive experiments make real causal progress despite incomplete overall recovery; a numeric failure count must not trigger a pointless restart.

The existing Field Lab schema, baseline/expected overlays and semantic-review boundary are reused. New deterministic fixture regressions check red/green delivery, residual symptoms, non-exempt paths and incorrect repairs. Expected reports are reference controls, never fabricated attempt receipts. Semantic requirements must be judged from real attempt evidence.

## Validation and release boundary

Run the repository's existing source/package gate and `python3 -m unittest discover -s scripts -p 'test_*.py' -q`. The focused controls can be run with `python3 -m unittest discover -s scripts -p 'test_diagnostic_fixtures.py' -v`. Exact-source CI, release receipts and publication state are recorded separately; this note and the version string do not establish them by themselves.

No paid model calls or live router changes are required by this release. Host installation, directory upload, website deployment and live model evaluation remain separate operations. Fixture success establishes fixture mechanics, not improved agent behavior. A future live attempt needs its own explicit invocation budget and review under the existing evaluation contract.
