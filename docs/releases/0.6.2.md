# Servotab 0.6.2

Maintenance and delegation-contract update for the quiet, risk-scaled engineering method plugin. The package retains one implicit router and twelve explicit methods while moving to a 70-file portable package layout.

## Changes

- Define LF as canonical text identity so Git for Windows `core.autocrlf=true` checkouts and equivalent CRLF retained by older worktrees do not create false stale-package reports; binary assets remain byte-exact.
- Add the portable root `plugin.json` with `extensions.com.openai` and retain the synchronized `.codex-plugin/plugin.json` compatibility fallback.
- Choose responsibility before deep execution: keep clear and trivial work direct, honor explicit solo requests, reuse one active worker, and allow one coherent bounded lane when delegation actually pays.
- Preserve coupled parts within one owner, forbid recursive delegation, and sequence locally when the host exposes no subagent capability.
- Add explicit tranche-planning and cross-process complete-delivery controls plus four delegation responsibility-choice canaries, bringing the source pack to seventeen cases.
- Separate deterministic trace and workspace assertions from semantic review. One independently budgeted workspace-scoped delegation attempt passed deterministic verification and all three receipt-bound review requirements; that evidence does not establish general model effectiveness.
- Refresh public package, release, website, and publisher-identity surfaces for 0.6.2.

## Package and upload

`servotab-0.6.2-source.zip` contains the repository marketplace and maintainer tooling. `servotab-0.6.2-plugin.zip` contains only the 70-file plugin payload for an owner-controlled directory upload. `release-receipt.json` identifies the exact source commit/tree and package manifest; `SHA256SUMS` checks both archives and the receipt. Verify the source provenance as well as the checksums.

## Evidence and limits

Deterministic validation covers canonical/generated identity, exact package ownership, parsed SVGs, decoded PNGs, package/release regressions, seventeen behavior fixtures, public-tree safety, website behavior tests, and the production build. The Windows CI job checks generated payload identity under Git for Windows defaults. Check the attached receipt and the exact source revision's GitHub checks.

The tagged GitHub release establishes public source and artifact availability for the exact release revision. It does not by itself establish installation, activation, OpenAI directory submission, review, approval, or publication. The website was deployed and verified separately after the GitHub release. Publisher/creator credit, licensing, privacy boundaries, and the skills-only product model are otherwise unchanged.
