## Changes

The release connects four existing decision points that the earlier releases already owned:

- `plan` selects an early executable path through the real entry point and material state boundary before it sequences the rest of the work, so the first slice closes a real observable outcome instead of only the easiest isolated piece.
- `execute` connects and observes that entry/state path before expanding peer features. It keeps risk-appropriate red-green work and the remaining accepted scope intact, so connecting slices never becomes a reason to drop tests, shrink the request, or defer the full outcome.
- `review-feedback` carries a confirmed correction to every consumer of the same shared contract while protecting legitimate exceptions and explicit write limits. It verifies the correction against the real contract rather than applying it to the reported symptom alone.
- The router and the explicit `execute` leaf keep one goal, plan, responsibility owner, evidence set, and remaining scope continuous across the methods that participate in a task, and withdraw investigation or ceremony whose purpose has ended instead of restarting the commission at each method boundary.

The router's implicit activation topology is unchanged. Clear changes still stay direct, and stronger method still appears only when risk, scope, or uncertainty warrants it.

## Evidence cases

The source pack now contains twenty-five cases; twenty-one declare non-empty `human_review_requirements`, and the twelve existing adversarial controls are unchanged. The package still contains one implicit router, twelve explicit-only leaves, and 70 manifest-owned files.

`feedback-correction-radius` is the new case. A confirmed review correction must reach every consumer of the same user-date contract while preserving the UTC audit exception and the exact write boundary. The prompt and the visible regression expose only the chart symptom and do not name the sibling consumers, so the repair radius must be derived from the implementation. An independent command oracle checks the complete user-date contract: chart, detail, and share output must move together, UTC audit semantics must remain unchanged, exact minute offsets must be preserved, and only `days.py` may change. Semantic review requires trace evidence that the agent derived that repair radius from the code rather than from the prompt alone.

The existing `complete-notes` case now reserves semantic review for whether the selected CLI and persistence path was actually exercised before broad migration and error-path expansion, early enough to inform later implementation rather than being checked only at final verification. Its deterministic complete-delivery oracle is unchanged.

New deterministic fixture regressions check the correction-radius control; expected reports remain reference controls, never fabricated attempt receipts. Semantic requirements must be judged from real attempt evidence, and deterministic success establishes fixture mechanics only.

## Validation and release boundary

Run the repository's complete deterministic source/package gate from [AGENTS.md](../../AGENTS.md) and the Python regressions:

```bash
python3 -m unittest discover -s scripts -p 'test_*.py' -q
```

When the standalone `fieldlab` CLI is available, the no-target-model subject checks are:

```bash
fieldlab validate fieldlab-pack.json
fieldlab selftest fieldlab-pack.json
fieldlab list fieldlab-pack.json
```

These checks establish source, generated-package, and deterministic fixture consistency for this source revision. They do not execute a target model, close declared semantic-review requirements, install or activate the package, deploy the website, or update the OpenAI directory. Exact publication state belongs in [current state](../current-state.md).

No paid model calls, live router changes, or network operations are required by this release. Any future live synthetic attempt needs its own plan and explicit invocation budget under the existing evaluation contract.
