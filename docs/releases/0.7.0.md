# Servotab 0.7.0 — strategy, continuity and incorporation

Servotab 0.7.0 brings Plan strategy, comparative Design/Debug judgments and the
Incorporate method into one release. It preserves one implicit router, twelve
explicit-only leaves and a 70-file plugin payload. No runtime service,
dependency, hook, mandatory report or new approval round is added.

## Changes

- **Plan strategy and task continuity.** A settled goal can still need decisions
  about sequencing, effort, evidence and recovery. `plan` chooses and revises
  the route, preserves the complete accepted outcome, and keeps a durable task
  record when continuity needs it. Resume from an explicitly selected task entry
  and reconcile it against current code and evidence. Router, Execute, Spec
  Chain, Delegate and Finish keep the same goal, record and responsibility owner;
  small clear work can remain inline. Planning does not switch the host into
  Plan Mode or grant implementation or publication authority.
- **Incorporate specified material.** `incorporate` replaces `review-feedback`
  and handles the appropriate effect of discussions, feedback, research and
  references on the target work. Cover important contributions before narrowing
  implementation priorities, interpret corrections in context, preserve
  explicitly selected forms and judge applicability. Open ideas can improve
  design, examples or checks without automatically becoming features. Carry
  adopted effects through the authorized implementation and verification.
  Technical review retains code-based verification, scoped finding dispositions
  and correction across shared-contract consumers. Design retains open choices;
  Delegate retains responsibility allocation. A reading lane can establish
  coverage, or one worker can own a complete bounded incorporation task.
- **Comparative judgments.** `debug` constrains selective-failure explanations
  with the closest verified working case. `design` names the condition that
  makes a recommendation preferable to its nearest viable alternative, and can
  separate conflicting properties by time, location, condition or scale when
  that helps the decision. Ordinary work requires no extra exercise.
- **Source and evidence alignment.** Current skill metadata, generated paths,
  icons, documentation and the Methods catalog use `incorporate`. The existing
  glyph is reused without geometry or raster changes; its SVG accessible title
  and description now name Incorporate. The source pack adds
  three Plan cases and two Incorporate cases, and supports named Plan studies
  in the read-only acceptance checker while retaining existing receipt checks.

## Upgrade and compatibility

Change explicit `$review-feedback` calls to `$incorporate`, including saved
prompts and method-path references. No compatibility alias or parallel leaf is
shipped. The method still handles verified technical feedback; the rename
broadens the entry to other specified material without dropping that guarantee.
Finding dispositions remain judgments; the old fixed category labels,
implementation-order ladder and scripted response wording are no longer required.
The existing `servotab@personal` marketplace selector and installation route are
unchanged. Published `v0.6.5` archives retain their original method set.

The source evidence pack has 30 cases, 26 with semantic-review requirements,
63 activation seeds and 19 adversarial controls. Deterministic package and
fixture checks establish source consistency and reject known wrong fixture
outputs; they do not establish general live-model effectiveness.

The earlier bounded Plan comparison accepted six candidate attempts and five
of six baseline attempts; one baseline recovery omitted unknown historical
publication state. That small synthetic comparison does not establish a
general effectiveness or efficiency gain. Full Plan behavioral acceptance
remains open. Supplied Incorporate trial reports lack independently inspected
raw traces; receipt-bound semantic acceptance and ordinary-language activation
are not established by this release. See [Plan coverage](../../evals/plan-strategy.md)
and [Incorporate evidence](../incorporate-candidate.md).

## Artifacts and publication boundary

The clean-commit release builder produces four exact-source assets:
`servotab-0.7.0-plugin.zip`, `servotab-0.7.0-source.zip`,
`release-receipt.json` and `SHA256SUMS`. The plugin ZIP contains only the
manifest-owned payload under one `servotab/` root; the source ZIP includes the
marketplace and maintainer tooling. Follow [Releasing](../releasing.md) for
the deterministic gate, exact-commit checks and downloaded-asset verification.
Current publication receipts belong in [current state](../current-state.md).

GitHub publication, OpenAI Directory publication, local installation and
activation, and website deployment have separate receipts. The last separately
observed public Directory version is `0.6.4`. This release supplies the ZIP for
an owner-controlled manual upload; it does not perform that upload. No new
live-model evaluation is part of release preparation.
