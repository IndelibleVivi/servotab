# Servotab 0.6.1

Release hardening for the quiet, risk-scaled engineering method plugin. One implicit router, twelve explicit methods, and the 69-file skills-only package remain unchanged in topology.

## Changes

- Validate real SVG XML and decoded PNG pixels, rejecting malformed assets, non-finite/undersized canvases, active content, external resources, truncated images, and source-format conversion.
- Reject ambiguous metadata, invalid manifest entries, unowned package content, and generator symlink writes.
- Clarify the ordinary test-criterion check: no mandatory mutation-testing stage or extra reviewer loop. Explicitly authorized foundational work remains possible.
- Prepare reproducible plugin/source ZIPs with exact-source receipts and checksums, gated by source/package/site CI.
- Reconcile release evidence and add two public behavior fixtures for reuse and false-green verification.

The release also carries the 0.6 source improvements: dependency-ordered design decisions, bounded reuse research, risk-matched verification and review disposition, race-safe homepage motion, and per-skill SVG canvases compatible with the observed upload-scanner minimum.

## Assets and installation

`servotab-0.6.1-source.zip` contains the repository marketplace and maintainer tooling. `servotab-0.6.1-plugin.zip` contains only the 69-file plugin payload for a separate owner-controlled directory upload. `release-receipt.json` identifies the exact source commit/tree and package manifest; `SHA256SUMS` checks both archives and the receipt. Verify the GitHub source as well as checksums.

From the extracted source directory, or a checkout of this release tag:

```bash
codex plugin marketplace add .
codex plugin add servotab@personal
codex plugin list --marketplace personal
```

Start a fresh Codex task/process and confirm the installed version. Older manifest-owned Softpowers installations must follow the migration guide; do not delete their directories by hand.

## Evidence and limits

Deterministic validation covers package and asset structure, canonical/generated identity, packaging/release regressions, behavior-fixture failure/repair controls, and nine website motion tests plus the production build. Check the attached receipt and the exact revision's GitHub checks. Fixture controls do not invoke a target model; no general model-effectiveness improvement or 0.6.1 named-host acceptance is claimed.

Maintainer validation requires Python 3.10+ and pinned PyYAML/Pillow from `requirements-dev.txt`. Neither is shipped in the installed skill payload. A GitHub release does not update the OpenAI directory or deploy the website. Publisher/creator credit, licensing, privacy boundaries, and the skills-only product model are unchanged.
